STATE MANAGEMENT ARCHITECTURE
════════════════════════════════════════════════════════════════════════════════════

Both platforms use ZUSTAND with identical patterns:

Authentication Store:
  ├─ user: User | null
  ├─ token: string | null
  ├─ login(email, password): Promise
  └─ logout(): void

Server Store:
  ├─ servers: Server[]
  ├─ currentServer: Server | null
  ├─ fetchServers(): Promise
  └─ createServer(name): Promise

Message Store:
  ├─ messages: Message[]
  ├─ addMessage(msg): void
  ├─ editMessage(id, content): Promise
  └─ deleteMessage(id): Promise

⚠️ NOTE: Stores are 60% duplicated between Desktop and Mobile
         (manual copy-paste, not shared via monorepo)

Future Improvement: Migrate to monorepo (Turborepo/Nx) for single source of truth


SECURITY ARCHITECTURE
════════════════════════════════════════════════════════════════════════════════════

Authentication Flow (Identical on both):
  1. User registers/logs in
  2. Backend validates credentials
  3. Issues JWT (access token) + refresh token
  4. Client stores tokens securely:
     Desktop: Electron secure storage (Windows DPAPI)
     Mobile: expo-secure-store (iOS Keychain / Android Keystore)
  5. Tokens sent in Authorization header for API calls
  6. WebSocket authenticated with JWT

Encryption:
  ├─ Credentials:     HTTPS (TLS 1.2+) on network
  ├─ At Rest:         DPAPI (Desktop) / Keychain (Mobile)
  ├─ Messages:        Plain text over HTTPS
  └─ Future:          E2E encryption (Signal protocol planned)

Threats Mitigated:
  ✅ SQL Injection      (Prisma ORM parameterized queries)
  ✅ XSS               (sanitize-html for user input)
  ✅ CSRF              (JWT token-based, no cookie dependency)
  ✅ Credential Theft  (Secure storage, HTTPS only)
  ✅ DDoS              (Rate limiting via express-rate-limit)


BUILD & DISTRIBUTION
════════════════════════════════════════════════════════════════════════════════════

DESKTOP BUILD:
  Development:  npm run dev:desktop
  Production:   npm run build (outputs dist/ folder)
  Package:      electron-builder (creates .exe installer)
  Distribution: GitHub Releases, Direct download from website
  Update:       electron-updater (auto-update checks)
  Size:         ~500MB-1GB standalone executable

MOBILE BUILD:
  Development:  expo start
  Android:      eas build --platform android (outputs .apk)
  iOS:          eas build --platform ios (outputs .ipa)
  Distribution: Google Play Store, Apple App Store, direct APK
  Update:       Expo EAS Updates (over-the-air patches)
  Size:         ~80-150MB APK


KNOWN LIMITATIONS
════════════════════════════════════════════════════════════════════════════════════

Desktop Limitations:
  • Windows only (no Mac/Linux native builds)
  • Large installation footprint
  • High memory usage
  • Bundled MySQL requires disk space
  • Not suitable for low-end hardware

Mobile Limitations:
  • Requires network for most features
  • Screen sharing not available (React Native limitation)
  • Limited voice codec negotiation (some Android devices)
  • Expo doesn't support all native modules
  • Offline mode limited to async-storage


CHOOSING THE RIGHT PLATFORM
════════════════════════════════════════════════════════════════════════════════════

Use DESKTOP APP if:
  ✓ Primary work device at desk
  ✓ Need screen sharing for presentations
  ✓ Prefer keyboard-driven interface
  ✓ Want offline capability
  ✓ Have 1GB free disk space
  ✓ Developing VOX features

Use MOBILE APP if:
  ✓ On-the-go messaging
  ✓ Commuting/traveling
  ✓ Prefer touch interface
  ✓ Limited storage space
  ✓ Need quick DM access
  ✓ Want app store experience
